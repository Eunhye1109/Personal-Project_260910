# 집에서 게임위 데이터 받기

사무실 IP 가 게임위(`www.grac.or.kr`)에 차단돼 있어 회사에서는 한 건도 못 받는다.
게임위 Open API 는 공공데이터포털이 중계하지 않고 게임위 서버를 직접 호출하는
**LINK(연계) 방식**이라, 포털 인증키가 멀쩡해도 IP 가 막히면 소용이 없다.

이 프로젝트는 개인 프로젝트이므로 회사망일 이유가 없다. **집 회선이나 휴대폰
테더링에서 받으면 된다.** 이 문서는 그 절차만 적는다.

---

## 0. 준비 (사무실에서 미리 해둘 것)

공공데이터포털에서 **`게임물관리위원회_게임 정보`(15120667)** 활용신청을 해둔다.
개발계정은 자동승인이라 신청 즉시 쓸 수 있다.
포털 접속(`www.data.go.kr`)은 사무실에서도 되므로 신청은 회사에서 해도 된다.

> 인증키는 계정당 하나이고 승인된 API 전체에 공통으로 쓰인다.
> 영등위 수집에 쓴 키를 그대로 쓰되, **게임 정보 API 활용신청이 별도로 되어 있어야 한다.**

---

## 1. 집에서 폴더 열기

NAS 의 이 경로를 연다.

```
Y:\2. 정책기획팀\기타\gucc_rating_analysis
```

집 PC 에서 NAS 를 잡는 방법이 회사와 다르면, 폴더째 내려받아 로컬에서 돌려도 된다.
어느 쪽이든 동작은 같다.

---

## 2. 인증키 넣기

**NAS 폴더의 `.env` 에 키를 쓰지 않는다.** 그 폴더는 정책기획팀 공유 폴더라
키가 팀 전체에 노출된다.

대신 스크립트가 알아서 물어본다. 처음 실행하면 이렇게 뜬다.

```
[DATA_GO_KR_KEY] 값이 설정돼 있지 않습니다.
  DATA_GO_KR_KEY = ▮
```

여기에 포털 인증키(Decoding 값)를 붙여넣으면 된다. 답은 그 PC 의 홈 폴더

```
C:\Users\<사용자>\.gucc_rating_analysis.env
```

에만 저장된다. NAS 로는 올라가지 않으므로 한 번만 넣으면 다음부터는 안 물어본다.

---

## 3. 순서대로 실행

### 3-1. 먼저 검증 (요청 15회 이하)

```
python src/probe_grac.py
```

이 스크립트는 데이터를 모으지 않는다. 다섯 가지만 확인한다.

| 확인 | 왜 필요한가 |
|---|---|
| 게임위 서버에 닿는가 | 집에서도 안 닿으면 IP 차단이 아니라 다른 문제라는 뜻 |
| 인증키가 필요한가 / 이름은 무엇인가 | 이 API 는 키 없이 될 수도 있다. 세 가지 이름을 차례로 시험한다 |
| 응답 필드가 무엇인가 | PRD 4.2절 수집 항목이 실제와 맞는지 |
| **descriptors 가 어떤 형태인가** | **가장 중요.** 아래 참조 |
| 기간·페이징이 먹는가 | 영등위에서 겪은 페이징 한계를 피할 수 있는지 |

> **descriptors 결과를 반드시 눈으로 확인할 것.**
> 영등위는 내용정보를 `1단계-낮음` ~ `5단계-매우높음` 의 **5단계 순서형**으로 준다.
> 게임위가 `선정성,폭력성` 처럼 **이름만 나열**하는 형태라면 두 매체를 같은 척도로
> 비교할 수 없다. 그 경우 영등위 값을 `3단계 이상 = 보유` 로 이진화해 맞춰야 하고,
> PRD 4.4절(척도 정렬)과 5.4절 축①의 설계를 고쳐야 한다.
> probe 가 이 판정을 화면에 찍어준다.

`--key-param` 을 무엇으로 줘야 하는지도 probe 가 알려준다
(`키 없이` / `serviceKey` / `key` 중 무엇으로 성공했는지 출력).

### 3-2. 한 달치만 시험

```
python src/collect_grac.py --months 1
```

`data/raw/grac_game/2016-01_p001.xml` 이 생기고, 합쳐진 parquet 이
`data/processed/` 에 떨어지면 정상이다.

키가 필요하다고 probe 가 알려줬다면 그 이름을 붙인다.

```
python src/collect_grac.py --months 1 --key-param serviceKey
```

### 3-3. 전량

```
python src/collect_grac.py
```

2016-01 부터 이번 달까지 월 단위로 잘라서 받는다. 중단해도 받은 조각은 남고,
다시 실행하면 건너뛰고 이어서 받는다.

한 번 실행에서 최대 300회까지만 보내고 멈춘다. 상한에 걸리면 그냥 다시 실행하면 된다.

---

## 4. 안전장치 — 왜 이렇게 조심하는가

2026-08 게임위 홈페이지 크롤링에서 **8병렬 · 누적 1만 건 이상의 POST** 를 보내
사무실 IP 가 차단됐다. 지금 겪고 있는 문제가 그것이다.

그래서 이 스크립트에는 다음이 코드로 박혀 있다.

1. **절대 병렬로 돌지 않는다.** 요청은 항상 순차 1개, 간격 1.5초.
2. 한 번 실행에서 보내는 요청 수 상한 **300회**.
3. 한 조각이 3회 실패하면 재시도를 반복하지 않고 **즉시 전체 중단**.
4. 서로 다른 달의 총 건수가 4번 연속 같으면 **기간 조건이 무시되는 것으로 보고 중단**한다.
   (조건이 안 먹는 채로 계속 돌면 같은 페이지를 수천 번 긁는 꼴이 된다)

집 회선에서 돌리더라도 이 상한은 그대로 둔다. 차단이 풀린 뒤 사무실에서
같은 스크립트를 쓸 수 있어야 하고, 무엇보다 상대 서버에 부담을 주지 않는다.
