## 4. 엔드포인트 문제 — 두 시간이 걸린 지점

인증키를 `.env`에 넣고 호출했으나 계속 실패했다. **원인 판별 과정이 핵심이므로 그대로 남긴다.**

**증상**
```
https://apis.data.go.kr/B551008/video_v2
→ HTTP 400  NO_OPENAPI_SERVICE_ERROR (코드 12) "해당 오픈API 서비스가 없거나 폐기됨"
```

**판별 ① — 다른 기관 API에 같은 키를 던져봤다**
```
기상청 API(주소가 확실한 곳) + 같은 키
→ SERVICE_KEY_IS_NOT_REGISTERED_ERROR (코드 30) "등록되지 않은 서비스키"
```
주소가 맞는 곳에서는 "키 문제"라고 답이 온다. 즉 포털은 **주소를 먼저 확인한 뒤 키를 본다.**
영등위 주소에서는 키 이야기까지 가지도 못했다는 뜻.

**판별 ② — 가짜 키로 던져봤다**
```
영등위 주소 + 가짜 키  → 코드 12 (진짜 키와 동일)
```
키를 보지도 않고 거부한다 → **키 문제가 아니라 주소 문제로 확정.**
http/https, 끝 슬래시 유무도 전부 동일했다.

**해결**
포털이 제공하는 `gateway_swagger_guide.pdf`(공통 안내서) 7페이지에 구성이 명시돼 있었다.
```
호출 URL = 프로토콜 + Base URL + 호출주소
예: http://apis.data.go.kr/AAAAAA/api/file-data-list
```
페이지 상단에 크게 보이는 주소는 **Base URL까지**이고, Swagger 목록의
`GET /호출주소` 를 직접 붙여야 한다.

```
확정: https://apis.data.go.kr/B551008/video_v2/video_search_v2
```

**교훈:** 코드 12와 코드 30을 구분하면 주소 문제와 키 문제를 가를 수 있다.
가짜 키 테스트가 가장 빠른 판별법이다. 이 해석은 `probe_kmrb.py`에 코드로 넣어뒀다.

## 5. 0단계 검증 결과

```
resultCode 00 (NORMAL_CODE) / totalCount 134,197 / 응답 필드 32개
등급분류일자 오름차순 정렬 (2009-01-06 ~)
```

**가정 A-1 검증 완료 — 통과**
내용정보는 5단계 순서형 척도로 제공된다.
`1단계-낮음 / 2단계-보통 / 3단계-다소높음 / 4단계-높음 / 5단계-매우높음`
→ 정제 규칙 확정: 접두 숫자 추출로 1~5 정수 변환.

**★ 새로 발견한 문제 — 내용정보 항목명 미상**
7개 항목이 `rtStdName1` ~ `rtStdName7` 로 **번호로만** 오고 이름표가 없다.
어느 번호가 주제·선정성·폭력성·공포·약물·대사·모방위험인지 API가 알려주지 않는다.
확정 전까지 항목별 해석이 불가능하다.
→ 영등위 공개 등급분류 결과에서 개별 작품 5~10건을 대조해 순서를 밝혀야 한다. **미해결.**

**그 밖의 데이터 특성 (2009년 상반기 1,000건 기준)**
- Y/N 플래그 6종(`pokFlag`, `yak*Flag`, `mo*Flag`)이 전건 `N` — 미입력 의심. 최근 연도 확인 필요
- `rtCoreHarmRsnNm` 전건 결측, `workCont` 99.8%, `prodYear` 86.5% 결측
- **성인물 77% · 청소년관람불가 81%** 로 표본이 크게 치우침
  → 게임물과 비교할 때 매체 차이와 성인물 비중 차이가 교란된다. 종별 통제 설계 필요

**리스크 R-4(호출 제한으로 수집 지연) 해소**
1,000건/호출 × 135회면 전량. 개발계정 일 1,000회 한도 대비 여유.

**API 함정**
`numOfRows`를 너무 작게(1) 주면 `resultCode 99 UNKNOWN_ERROR`가 난다.
실제로 쓰는 크기와 같은 값으로 물어봐야 한다.

## 6. 1단계 수집 착수

`src/collect_kmrb.py` 작성. 페이지 재시도, 이어받기(이미 받은 페이지 건너뜀), `rtNo` 기준 중복 제거 포함.

**응답이 느리다: 1,000건당 약 50초** → 전량 135회에 1~2시간.

### 안전장치 (사용자 지시)

과거 게임위 크롤링에서 **8병렬·누적 1만+ 요청**으로 사무실 IP가 차단된 전례가 있어,
같은 일이 반복되지 않도록 다음을 코드에 박아뒀다.

1. 절대 병렬로 돌리지 않는다. 요청은 항상 순차 1개
2. 한 번 실행당 요청 상한 `MAX_REQUESTS_PER_RUN = 200`
3. 페이지가 3회 실패하면 재시도를 반복하지 않고 즉시 전체 중단
4. 개발계정 일 한도(1,000회) 대비 여유 확보

현재 부하: 순차 1개, 시간당 약 72회, 총 135회 = 허가 한도의 13.5%.
게임위 때(홈페이지 크롤링·8병렬·1만+ POST)와는 성격이 다르다.

**반성:** 페이지 크기를 재보겠다고 큰 요청을 여러 번 던졌고 두 번 다 타임아웃이 났다.
클라이언트만 끊기고 서버는 계속 처리하므로 이것이 실제 부하였다.
**속도 측정 같은 불필요한 대량 호출은 하지 않는다.**

## 7-2. 3단계 현황 EDA (99,000건)

**표기 체계 정정 — 내가 틀렸던 지점**
처음에 "2017년 이후 내용정보 없음(51,054건 결측)"으로 판단했으나 **오판이었다.**
변환 코드가 `N단계` 형태만 인식해 뒤쪽 체계를 전부 결측 처리한 것.
실제로는 2017-05부터 표기가 `전체관람가~제한상영가` 로 바뀐 것이고, 둘 다 5단계 순서형이라
1:1 대응된다. 2016년(단계표기)과 2018년(등급표기)의 항목별 평균 차이가 -0.06~-0.21로
거의 같아 대응이 타당함을 확인했다. 수정 후 결측 51,054건 → 1건.
`content_notation` 컬럼을 만들어 시기별 비교 시 통제할 수 있게 했다.

**주요 결과**
- 청소년관람불가 비중 2009년 81.9% → 2023년 17.2%. 전체관람가는 8.9% → 47.7%.
  2016년이 변곡점. 심의 기준이 아니라 신청 대상 자체가 바뀐 것으로 보인다.
- 종별: 성인물 43.3% / 기타 29.6% / 극영화 13.7%. 성인물 편중은 게임물 비교 시 통제 필요.
- **등급별 내용정보 프로파일: 전체관람가는 7항목이 전부 정확히 1.00.**
  하나라도 2단계 이상이면 전체관람가가 나오지 않는다는 뜻.
- **조합 효과(축②의 직접 근거): 3단계 이상 항목이 1개면 청불 5.4%, 4개면 93.4%.**
  단 5개에서 71.5%로 꺾인다(비단조) — 특정 조합이 따로 작동할 가능성.
- 신청등급과 결정등급 조정 11%(상향 7.5% · 하향 3.4%). 상향 7,474건 중 4,210건이
  전체관람가로 신청한 건.
- **항목 간 상관이 두 덩어리로 갈린다: {1,2,4,7}(0.67~0.88)과 {3,5,6}(0.43~0.71),
  두 덩어리 사이는 0에 가깝거나 음수.** 항목명이 확정되면 이 구조를 해석할 수 있다.

**수집 중단 지점**
약 99,000건(pageNo 100)부터 `resultCode 99`. pageNo 101·135도 동일, numOfRows를 500으로
줄여도 동일 → 깊은 페이지 조회 자체의 한계. 날짜 조건으로 나눠 받아야 하는데
옵션 파라미터명을 모른다. 추정 6종(gradeName·kindName·rtDate·rtYear·startDate 등)을
시험했으나 **전부 무시됨**(totalCount가 134,197로 불변). Swagger의 요청변수 목록 확인 필요.

## 7-3. 내용정보 항목명 추정 (미확정)

공공데이터포털 메타데이터(DCAT)에 **공식 항목명 7종**이 명시돼 있다.
> 주제, 선정성, 폭력성, 공포, 약물, 대사, 모방위험성

이름은 확정됐으나 **`rtStdName1~7`의 번호 순서와 같은지는 별개 문제**이고,
데이터는 순서대로가 아니라고 말한다.

**근거 — 성인물(42,892건)과 극영화(13,527건)의 항목별 평균 차이** (양수 = 성인물이 높음)
```
항목1 +1.24   항목2 +1.92   항목3 -1.23   항목4 +1.19
항목5 -0.76   항목6 -0.99   항목7 +0.98
```
- 항목2가 성인물에서 가장 높다 → **선정성**으로 거의 확실
- 항목3·5·6은 극영화에서 더 높다 → 폭력성·약물·공포 계열
- **순서대로면 항목4=공포인데 성인물에서 +1.19로 높다. 말이 안 된다.**
- **순서대로면 항목6=대사인데 성인물에서 -0.99로 낮다. 이것도 말이 안 된다.**

**유력 가설: 4와 6이 바뀌어 있다.**
```
1 주제 · 2 선정성 · 3 폭력성 · 4 대사 · 5 약물 · 6 공포 · 7 모방위험
```
이러면 상관 덩어리도 해석된다 —
{1,2,4,7} = 주제·선정성·대사·모방위험(성인물 축), {3,5,6} = 폭력성·약물·공포(극영화 축).

**아직 확정 아님.** 성인물·극영화의 성격에 대한 상식적 가정에 기댄 추론이다.
확정하려면 ① 영등위 공개 등급분류 결과에서 개별 작품 대조, 또는
